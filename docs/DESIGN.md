# Youth Academy Manager — design notes (current: v3.14)

Single-file game built from `src/` (see README / CLAUDE.md). EN/RU, Win98/CRT look, PT Sans (PT Mono in ReadMe). Static scanlines + soft vignette always on; rain/glare via "Screen effects" in the Start menu. Save: localStorage `yam_save_v1` (save format `v: 4` + `seasonStats`); last seen app version `yam_seen_version`.

## Versioning (strict)
`APP_VERSION` in `src/js/08-version-patch-notes.js` is the single source of truth → `<title>` (injected by `build.js`), `document.title`, taskbar `#app-title`, tray badge, ReadMe.txt. Newest `PATCH_NOTES` entry must match (build fails otherwise). Every change = new version + EN/RU notes + git tag.

Version map: v0.1 MVP · v0.2 Russian + readability · v0.3 roles/shouts/energy · v0.4 formations + radar + speeds · v0.5 league/calendar/dashboard · v0.6 Team Management + modals + Win98 polish · v0.7 60 FPS live pitch · v0.8 Smart Swap · v0.9 Game Feel + ReadMe · v1.0 Coach's Notebook 2.0 · v1.1 Touchline · v1.2 GitHub, modules, WebP · v1.3 softer vignette, Match icon above ReadMe. (Git history starts at v0.3; v0.1–v0.2 were not archived.)

## Navigation & loop
Main nav: Dashboard | Team Management | League Table. Match and Notebook appear only while the calendar unlocks them. ReadMe.txt: desktop icon / Start menu / tray badge.
Loop: Dashboard (calendar) → matchday modal → Team Management → Match (half-time pause, subs) → full-time modal → Notebook (roles) → Return to Dashboard → next matchday. 18 matchdays → season end → new season.

## Systems (00-utils-data.js, 05-game-state.js)
- Hidden attributes: see "Attribute system (v1.8)" below — never displayed outside DEBUG.EXE.
- Roles (one per player, set in Notebook): Aggressive (Tackle ×1.5; lost visible duel → foul + yellow, 2nd = red), Playmaker (Pass ×1.5, passes more), Selfish (Dribble/Shoot ×1.5, rarely passes).
- Energy: in-match live drain 30–40% over 90'; every roll × `fatigueMult(live energy)` (v3.4: 1 − 0.1·(1−x)², 1.00 → 0.90, see below); half-time +4; after match players keep real energy, unused subs +6; rest day +4. Squad 16 (11 + bench GK, DEF, MID, MID, FWD).
- Formations (10): slot lines DEF/MID/ATT decide who contests each third; `presence()` → line superiority ±4 (normalised: 4-4-2 vs 4-4-2 = 0); out of natural line ×0.85.
- Shouts: Attack/Defend ±3 to our attacking/defending rolls.

## League & calendar (04-league-calendar.js)
10 teams, double round-robin (circle method), Saturdays from 7 Sep 2002. AI strengths [3,2,1,1,0,0,−1,−2,−3] (hidden), AI rosters generated once per club. AI-vs-AI: Poisson, λ_home = 1.1 + Δ·0.035, λ_away = 0.85 − Δ·0.035 (rating = 50 + strength·4) ≈ 1.9 goals/game. `CalendarEngine.registerType(type, {blocking, label, onArrive})` + `onDay(fn)`.

## Match engine (06-match-engine.js)
- One headline action per minute (pass / dribble / shot = aim → strike → outcome), roll = (attr·multipliers + rand·10 + mods) vs (defender attr + rand·10 + mods).
- `ambient()` background play per minute (stats only): pass chance GK .05 / DEF .09 / MID .17 / ATT .07, take-on DEF .02 / MID .08 / ATT .15, rand·16 spread. Per match ≈ MID 17 passes, DEF 11 duels, ATT 14 dribbles. Results unchanged by it.
- Half-time: pause at 45' (`halfTime()`, `pause()`, `resume()`).
- Live subs: `substitute(outId, player)`, max 5, same slot, GK rules, no return.
- Tempo: 1×/2×/5× = 900/450/180 ms per minute; shot beats 1200/900/650 ms.

## Live pitch (09-live-pitch.js)
`MatchEngine` (events, `evLog`) → `PitchModel` (data: positions, targets, facing, ball path, trail/power, zoom hint, fx queue) → `PitchRenderer` (translate3d, camera 130% world + lazy lerp + push-in, trails, barks, facing notches, sub swap) → `MatchView` (one rAF loop, ≈0.05–0.3 ms/frame). Shake + CRT surge via UI hooks; reduced-motion respected.

## Screens (12-ui.js)
- Team Management: roster left, tactics board right; click/drag swaps; Smart Swap Highlighting (same position green, others dimmed but clickable).
- Match: three columns — live roster & subs | scoreboard, pitch (`.cam-holder` size container), log, shouts, speed | assistant coach (`assistantMessages`) & live stats.
- Notebook: 3 random players who played; "ok/total (rate%) (Season Avg)", colours >75% green / <40% red, `coachNote()` hint (11-notebook-helpers.js).

## Known balance observations
- v3.3: shouts retuned (`SHOUT`), fatigue is a smooth curve — see "Match engine balance (v3.3)" and v3.4.
- Engine sensitivity: one roll point on every duel ≈ ±40% goals (the chain pass → dribble → shot vs keeper multiplies). A club +3 on every skill beats an average one ≈ 2.9–0.0; that gap amplification is NOT addressed yet.
- Correct roles are strong (×1.5). Background duels never produce cards.

## League statistics (v1.7)

- Every AI club has `team.squad`: 14 lightweight kids `{ id, name, pos, mp, goals, assists }` (no attrs, no faces). Ids are `t{teamId}_{i}`; the full match roster (`League.roster`) is built FROM this squad, so names and ids match.

- Old saves: missing `squad` is generated on load, keeping the names of an already generated match roster.

## Attribute system (v1.8)
- `Player` (03-player.js) carries nested groups: `bio` {age 13–15, height, weight, strongFoot L/R, weakFoot 1–5} (position stays `p.position`), `physical` {acceleration, speed, agility, strength, baseStamina}, `technical` {firstTouch, dribbling, passing, crossing, shooting, tackling, goalkeeping*}, `tactical` {positioning, vision, decisions}, `psych` {passion, discipline, composure, potential = growth room 1–10 (v3.12; v3.11 ceiling 1–20; before PA 1–100)}, `dyn` {condition, sharpness, morale 0–100}. *`goalkeeping` was added on top of the brief so keepers have their own skill.
- `p.energy` is a getter/setter for `dyn.condition`; `p.age` reads `bio.age`. Old `attrs` are gone; `AttrGen.fromLegacy()` derives stable values from pre-v1.8 saves (seeded by id+name). Ranges per position: `PROFILES` in 00-utils-data.js; AI clubs add `team.strength` to every skill.
- Engine composites (`COMPOSITE`, `p.rating(key)`): Pass = passing+vision · Mark = positioning+2·tackling (reads passes, blocks shots) · Dribble = dribbling+agility+firstTouch · Speed = acceleration+speed · Tackle = 2·tackling+strength+positioning · Shoot = 2·shooting+composure · Save = 2·goalkeeping+agility+positioning.
- Global modifiers: sharpness < 50 → every technical skill −2 (`p.skill()`); condition = `fatigueMult(live energy)` (v3.3; was ×0.5 / ×0.8 steps); `moodBonus` = (morale−50)/25 × (0.55+passion/20), capped ±2.5, added to every roll. Pass also gets receiver firstTouch ±1.5 and crossing ±1 for balls into the final third. Decisions ≤7 → extra long shots from midfield, ≥15 → more passing. Drain × (1.15 − baseStamina·0.015).
- Dynamics: rest day −1 sharpness (floor 20), morale drifts 1 toward 60. After a match (`applyMatchDynamics`): sharpness full game +12, sub +6, unused −2; morale W +8 / D +1 / L −6, +5 per goal, −10 red, unused −2, × (0.6 + passion/25). Discipline is stored but not yet used.
- Balance check (600 sims, 6 random squads): win% 34 vs 36 in v1.7, pass % 68 vs 70, goals similar.

## Quick Sim (v2.0)
- `MatchEngine.tick()` is the whole match maths for one beat (minute, drain, action, ambient, half/full time). Drivers: `start()` = setInterval paced by SPEED/HIGHLIGHT with `notify()` → `hooks.onUpdate` each beat; `runInstant()` = synchronous loop over the same `tick()` (≈110 iterations, ~2 ms), `instant = true` → no timers, no onUpdate/onGoal, half-time gives the same +4% without pausing. `onLog`, `onEnd` still fire.
- UI: `createEngine()` shared by Start and `#btn-instant` (`onInstantSim()`): pre-match → whole match; half-time / mid-match → "SIM TO FULL TIME" plays the rest (subs + shouts kept). `onMatchEnd` records everything as usual; with `eng.instant` it skips the full-time dialog and opens the Notebook.
- Smoke test: with a seeded `Math.random` the visual and instant drivers produce identical scores, stats and energy (3 seeds).

## Consequences: queue, steps, match-day events, injuries & suspensions (v2.2)
- Event fields: `when: 'day' | 'matchday' | 'scheduled'`. `trigger(state, date, ctx)` (`ctx` = matchContext on match days). Choice extras: `next: '<step>'` (multi-step: same event re-executes with `ctx.step`, saved in `pendingEvent.step`), `debt: n` (forced payment, never disabled, may push the budget below $0), `ctx.schedule(id, { days | date, matchDay })` inside `run()`.
- `state.eventQueue` `[{ id, due, matchDay, from }]` (saved). `roll()` (non-match day) first fires a due non-matchDay item, then random `day` events (cooldown, `enabled`). `rollMatchDay()` runs in `onMatchdayArrived` BEFORE the matchday dialog: due matchDay items first, then random `matchday` events; `pendingEvent.after = 'matchday'` → `afterMatchdayEvent()` shows the matchday dialog. Queue items ignore `enabled` and the cooldown. A matchDay item due on a non-match day waits for the next match day.
- `player.injuryDays` (calendar days; `tickInjuries()` on every rest day AND on the match day in `closeMatchday`) and `player.suspensionMatches` (−1 after every match he did not play). `player.available` = no injury, no ban, no `Benched` flag. `swapPlayers` returns `unavail_inj|sus|deal`; `MatchEngine.substitute` returns `unavail`; `ensureAvailableXI()` replaces unavailable starters (same position, best overall) after every event choice, on match-day arrival and in `createEngine()`. Badges: `UIController.statusBadge()` (✚ days / red card matches / $ deal).
- After a match (`applyAvailabilityAfterMatch`): bans tick, `Benched` cleared, red card → 1-match ban, a knock becomes an injury 35% of the time (4–12 days).
- Events: `bus` (match day, away only, 20%: −$50 / condition ×0.7), `knock` (4%: −$200 → 3 days / 14 days), `ulti` (discipline < 8, 5%: fine +$20 & morale −10 / office → step 2: 2-match ban or discipline −2 & morale +5).

## Scout + Dads' pool (v2.3) — replaced the betting businessman (`sponsor`/`favor`, removed: kids' league)
- Queue items may carry `cast` (`ctx.schedule(id, { …, cast })`); `fire(id, date, { cast })` reuses it if every kid is still in the squad, else falls back to `event.cast()`.
- `scout` (day, 5%, after MD1, once per season): +$500 kit money → `scoutvisit` 14 days later on a match day. `scoutvisit` (scheduled): top 3 FIT kids by overall. After the match: −15 extra energy, 25% (×2 if exhausted) injury 3–8 days, diary `scout.done/hurt`. B: forced −$500 (`debt`), budget < 0 → team morale −20. Future hook: the scout can come back to poach a kid.

## Training days + Monday-first calendar (v2.4)
- **v3.13:** `isTrainingDay` (Tue/Thu) now only drives the AI clubs (`league.aiDay`); our training days come from the weekly plan — see "Weekly plan + CONTINUE (v3.13)".

Training: fit kids (not injured / kept at home) roll `skipChance(p) = max(0, (10 − discipline) × 3%)` → skip (no change, `skipped_training = true`) or attend (condition −10, sharpness +5). Rest days (and unfit kids on training days): condition +10 (`ENERGY.DAILY_REST`, was 4), sharpness −2 (was −1). Weekly net for a regular: +20 condition, +2 sharpness (+12 for a full match).

- `truant` (training, someone skipped, 60%): cast = a skipper. A: −$20 (disabled under $20), discipline +2 (the brief's "+10" mapped to the 1–20 scale). B: 1-match ban, morale −10. C: `next: () => roll` → step `sorry` (discipline +2) or `hangup` (morale −10); the rolled step is saved, so a reload can't re-roll. Choice `next` may now be a function.

## Match engine balance (v3.3)
- **Harness**: `node test/balance.js [N=500] [seed=33] [--pairs K] [--json]` — loads the real engine in a `vm` context (00-utils-data, 03-player, 06-match-engine), two fixed equal 4-4-2 squads (team seed 5, Neutral scoring ≈ league average), seeded `Math.random`, `runInstant()`. Mirrored: squads and home/away alternate. Table 1 = whole-match shouts; table 2 = neutral to 60', then the side ±1 goal shouts; `--pairs` averages over other random squads. Exit 1 if Attack-vs-Defense win share (W/(W+L)) leaves 45–55%. The smoke test runs it.
- **Engine**: `opts.oppMentality` = the away side's shout (AI stays `balanced`; only the harness uses it). `mod(side, role)` adds `SHOUT[m][role]`.
- **Why Defense "won"**: every duel is *our atk vs their def*, so the old shout (+3 own atk, −3 own def) shifted the attacking rolls of **both** teams by the same 3 points — it never tilted the match, it only scaled goal volume (Attack ×2.7 → 6.1 goals, Defense ×0.3 → 0.7). Defense therefore froze the score for free: a team leading by one at 60' won 90% with Defense vs 81% neutral and 66% with Attack; Attack was pure chaos. (Proof: in table 2 "leader shouts X" and "trailer shouts X" give identical results.)
- **Shouts now** (`SHOUT` in 00-utils-data.js): Attack `atk +1.0 / def −1.0`, Defense `atk −1.05 / def +1.0` (a small price for safety), Neutral 0. Attack ≈ +45% goals both ways, Defense ≈ −30%, Attack vs Defense ≈ 50%. The dial is still symmetric by construction; a real situational edge (e.g. Attack costs stamina) would be a separate design step.
- **Fatigue**: `fatigueMult(e) = 1 − 0.5·(1 − x)·(1 − 0.8x)`, x = e/100 clamped = 0.5 + 0.9x − 0.4x² → 100% 1.00 · 75% 0.95 · 50% 0.85 · 25% 0.70 · 0% 0.50, monotonic. Applied in `eff()` to LIVE energy (replaces "started < 50% → ×0.5" and "live < 30% → ×0.8"; `ENERGY.EXHAUSTED_MULT` removed). `eng.tired` stays only as a report flag (Notebook note). UI energy bars show `×fatigueMult` under 50%.

## Potential 1–20 (v3.11)
- `psych.potential` is now 1–20 on the same scale as the skills and IS the growth ceiling: `potentialCap(p)` = potential (`POTENTIAL` {MIN 1, MAX 20, DEFAULT 13} in 00-utils-data). Two scales by design: 1–20 = who he is (skills, psych, leadership, potential), 0–100 = how he is now (condition, sharpness, morale, rep).
- Roll: `clamp(round(10.2 + avg(r,r,r)·9.1 + mod·0.28), 1, 20)` = the exact old cap curve (PA 30–95 → 10–19), same 3 random calls. Migration: a stored value > 20 can only be old PA 1–100 → `potentialFrom100(v)` = clamp(round(6 + v·0.14), 8, 20) (PA 70 → 16).
- Growth chance × `growthMult(p)` = 0.6 + (potential − 6)/14 (same numbers as 0.6 + PA/100). `growSkill()` now picks only among the group's skills below the ceiling (still one `pick` = one Math.random), so a lucky roll is never wasted on a maxed skill; returns `'plateau'` when the whole group is capped.
- Plateau clue (fog of war, words only): first time a kid's group is capped on a successful roll → `p.plateau` (saved, groups) + diary `tr.plateau.<physical|technical|tactical>` once per group.
- Draft stars use `(potential − 13)/3.5` (= old `(PA − 50)/25`). Torn Boots' top-6 potentials break 1–20 ties by overall. DEBUG.EXE PA column max 20.

## Growth room + yard notes (v3.12) — replaces the v3.11 ceiling
- `psych.potential` (HIDDEN) = growth room 1–10: every trainable skill can gain that many points above its START value, hard max 20. `p.gains` {skill: points gained} (saved on every Player; `Player.generate` passes `gains: {}`). `canGrow(p, g, k)` = gains < room && value < 20; `growSkill()` picks only those (one `pick` = one Math.random); `'plateau'` when the group has none left (diary clue as in v3.11).
- Roll: `round(2 + avg(r,r,r)·6 + mod·0.2)` (same 3 calls) + `GROWTH.AGE` {13: +1, 14: 0, 15: −1, 16: −2}, clamp 1–10. 3000 kids: room 3–7 ≈ 95%, avg by age 13/14/15 = 6.0/5.0/4.0, correlation with overall ≈ 0 (late bloomers / early peakers by design). `growthMult` = 0.6 + room/10.
- Migration: a save without `gains` stored a ceiling (v3.11: 1–20; older PA > 20 → 6 + PA·0.14) → `roomFromCeiling` = clamp(ceiling − overall, 2, 10), computed after `dyn` (overall needs sharpness).
- Draft: stars removed. `DraftView.notes(p)` = up to `YARD.MAX` 2 traits whose value ≥ `YARD.SHOW` 14 (`YARD.TRAITS`: pace/dribble/pass/shot/tackle/hands = engine composites, engine/strong = raw stamina/strength −1), each wrong with 20% (a random other trait), seeded `'yard' + id`; none → `quiet`. i18n `yard.*`, tooltip `draft.notesTip`, CSS `.dr-notes` (pencil italic). Distribution: 0/1/2 notes ≈ 31/42/27 %. Notes never reflect the growth room.
- DEBUG.EXE: ROOM (max 10) + GAIN (total gained). Torn Boots' "talented kid" = top 6 by room (ties → overall).

- **Our training days**: `isOurTraining(date)` = date in the current week, `plan[weekKey]` set, no match that day. `planOf(date)`, `todayPlan()`, `trainingIndex(date)` (0-based number in the week), `trainingsPlanned()`. `dayRoutine(date)` defaults to them; AI clubs keep `isTrainingDay` (Tue/Thu) in `league.aiDay`. `EventEngine.roll` evaluates `when: 'training'` events on our training days. `UIController.dayInfo` → 'training' from the plan (earlier weeks: from the diary's `cal.training*` lines).
